# Benchmark report: 1000000-user social network

Generated by `examples/million_users.c`. Every analysis is one library call on the whole network, timed over 5 run(s);
every answer is checked by independent code in the example (not by the library), so a fast wrong answer does not score.

## Result cache (first call against repeat call)

A second copy of the network with the result cache enabled (the scored graph has it off, so the analyses above time the computation). Median of 5 repeats; each repeat is compared byte for byte with the first answer.

| Call | first call | repeat (cache hit) | speed-up | repeat identical |
|---|---:|---:|---:|---|
| connected components | 127.12 ms | 1.3219 ms | 96x | yes |
| BFS from the most popular user | 140.44 ms | 2.5025 ms | 56x | yes |
| Dijkstra from the most popular user | 376.16 ms | 3.4330 ms | 110x | yes |

Counters after the run: 15 hits, 4 misses, 4 stores, 3 invalidations, 3.8 MB held. After one new friendship the next components call recomputed and found one group fewer (passed), so the cache did not serve a stale answer.

A repeat is not free: the stored answer is copied out, so its cost grows with the result size (4 to 12 MB here).

## How to read and reproduce this

- **Reproduce:** `make bench-million` (rebuilds everything with `-O2` in `build-o2/`, then runs this example). Compare with an earlier run: `make bench-million BASELINE=old/results.csv`.
- **Suite score:** the geometric mean, over the scored analyses, of friendships processed per second of wall time in the best of the repeated runs (the run least disturbed by other programs). It is one comparable number; the table above is the real result. PageRank and Louvain do many sweeps per call, so their rates are lower by design.
- **Independent checks:** each analysis is verified by code in this file that uses only the generator's own edge list (union-find for groups, a recomputed modularity for communities, a fresh power-iteration step for PageRank, brute-force counting for clustering and suggestions, ...). A failed check marks the stage FAILED and the run exits non-zero.
- **Caveats:** one machine, one network from one seed; timings include nothing but the library call (no drawing, no I/O); the library is single-threaded so extra cores do not help; an unoptimised (-O0) build measured 1.3 to 1.7 times slower than -O2 on these analyses (the algorithms are memory-bound), so never compare numbers across build flags. On a shared laptop the same analysis varied by up to 2x between whole runs (five complete runs of this benchmark scored 3.7 to 7.1 million friendships per second, because other programs and CPU frequency scaling change the speed), which is why the score uses the best of 5 runs and the load average is recorded; expect a spread of tens of percent unless the machine is idle
